# 第一阶段：范围与安全裁剪

## 阶段目标

建立可重复启动、可调试、范围清楚的 WSL 本地基线；不是完成全部课程功能。保留当前 React/Vite、Express、MongoDB 和核心数据结构，Redis 第一阶段保留，避免同时重构队列/缓存/限流。

## 保留能力

现有简历导入、编辑、保存、版本及导出；个人资料；JD 粘贴与技能分析；简历驱动的普通模拟面试、语音输入/播报及历史反馈。若上游实现不完整，需真实记录并修复本阶段关键链路，不能仅依赖 README 宣传。

## 延后但不能误删的课程要求

师生与校友身份、岗位人工录入、技能自评、企业时间/技能要求、教师推荐学生、定向简历批量下载、公开上线及十余位真人使用证据。第一阶段保留相关模型和通用服务，不把“个人岗位搜索”当成“学校岗位发布”，也不把简历匹配当成教师荐才。

## 裁剪原则

1. 先清点入口、路由、共享服务、模块顶层副作用和数据模型，记录基线，再修改。
2. 未配置凭据前，禁用支付、邮件、外联、部署、爬虫、定时同步等外部副作用，不能先完整启动触发它们。
3. 前端取消导航和路由，后端停止路由注册、模块加载和后台任务；仅隐藏按钮不算停用。
4. ESM 的静态 import 会先于条件执行。对有副作用的停用模块改为条件动态导入/显式初始化；仅把 app.use 放进 if 不够。
5. 引用检查与基线回归通过后才物理删除；有动态注册/字符串路径/公共资源的不确定引用时保留，写出原因。
6. 共享上传/解析/导出、鉴权、数据隔离、安全中间件、通用组件、许可证和测试禁止粗暴删除。
7. 一次一个模块或一个工作包，测试失败立即定位该批改动，不以重新生成整站替代修复。

## 不做

不换 Vue/FastAPI/MySQL；不重建完整设计系统；不开发支付、作品集、社区；不为减少依赖立刻删除 Redis；不做云部署、真实电话呼叫接入、完整视频分析、教师后台、批量导出或校园岗位库；不引入微服务/Kubernetes；不在本阶段搭建多套并行工作树和自动发布流水线。

## Git 与授权

保留 LICENSE 和上游历史，记录上游 SHA 与本地差异；禁止覆盖用户修改、reset --hard、git clean、自动 stash、强制推送。只在专用分支工作；不自动提交/推送。已有 Trellis 的提交审批规则仍适用，未满足提交/合并条件不自动归档任务。
