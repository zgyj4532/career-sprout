# 设计

## 主流程

上传结束后直接显示整理结果。顶部一句摘要，例如「将补充 2 段经历、4 个技能，有 1 处需要你决定。」没有问题时按钮是「保存并继续」。有问题时按钮是「处理这几处」，另有「先保存其余内容」。原件和全文在入口里，不铺在主界面。

手机只有一个面板。点来源再返回时恢复滚动位置。保存按钮固定在底部。

## 读取

PDF 按页记录：有文字、疑似只有页眉、或这一页几乎没有文字。DOCX 记录正文文字和内嵌图片是否占主要部分。图片记录序号。某一块失败不影响已完成的块。

「继续读取」从失败的那一块往后做，复用原件和已有转写。模型结果也按块存下，恢复时不重叫。

Word 预览叫「内容预览」。用解出的文字显示，不承诺版面。若以后改用 HTML 转换，要去掉脚本和外部地址，并禁止访问外链。

## 整理

模型输入包一层数据边界，不执行其中的指令。输出只能是约定结构。服务端决定所有者和 `draft` 状态。

程序检查：依据短句在来源段落或图片序号里；数字集合不增加；否定词和「参与 / 负责」一类程度词没有被加强。做不到的关系检查标成待确认，不写入已证实字段。

日期保存原文、精度和是否至今。教育年份只在年份明确时另存一份，不替代原文。经历全文放在单独字段，精简稿是另一份可选文本。现有 150、2000、3000 字上限只限制精简稿和现有短字段，不裁全文。奖项、证书、联系方式进「其他原文材料」。档案页之后的保存必须提交并保留这些字段。

合并只产生候选。候选同时看机构、学历、时间和内容。不确定就问一句，默认不合并。固定 ID 的算法是 `草稿 ID + 来源块编号`，只用于同一次确认的重试。新的上传是新草稿。

## 保存

点保存时把当时的结果冻成一份确认单。执行单包含租约到期时间，以及每步的目标 ID 和「已确认存在」。

恢复规则：

- 租约过期：可以重新进入保存，不另开一份。
- 有 ID 但记录不存在：补建。
- 记录已存在：认作自己的写入，不因为版本已变成自己写过的值而返回冲突。
- 档案或成长材料在冻结之后被别的页面改过，且不是这次写入：返回冲突。

保存简历时只填空位。比较的是冻结时刻的正文。已经有的句子不重写。

保存成功后原件仍在草稿里。变更记录包含保存前版本。恢复只回放到那次导入之前，并且当时之后没有新的 `revision` 才能恢复；有新修改就拒绝。学生点丢弃才删除原件、提取文本和整理结果。

## 版本

简历增加两个整数：`revision` 每次标题或正文变化都加一；`contentRevision` 只有正文变化才加一。定向草稿改绑 `contentRevision`。

正文保存的更新条件是 `revision`，请求里不带标题。改名的更新条件也是 `revision`，只改标题和 `revision`。因此页面 A 拿着旧 `revision` 保存正文时，盖不住页面 B 已经完成的改名。

## 缓存

档案写入和缓存失效是两条状态。失效失败时接口仍返回已保存，并留下待刷新标记。补做只调用现有的缓存失效。校园读档案、生成简历和开始面试都直接读数据库，不读 120 秒缓存。

## 删除

先把简历改成删除中。版本、评分历史、分享、评论、定向草稿和导入恢复看到删除中就拒绝新建。清理完成前不报成功。导入恢复若发现目标简历已删除或删除中，停止并说明，不重建。

## 容量和重任务

上传用流式落盘。开始前原子预留这次最大可能占用，结束后按实际占用结算，失败释放。临时文件、解压残留和提取文本计入。

重任务开关只在解析、解码或启动浏览器前占用，慢速上传不占用。检查限制发生在解析过程中：Word 解压累计超过 20MB 就停；图片在解码前看头部尺寸，并限制帧数；PDF 边读边数页。20 秒解析超时要终止隔离进程，确认进程退出后再释放开关。模型请求另有 60 秒超时。

全局 500MB 满时，学生可以丢弃自己的草稿。自己没有草稿就返回稍后再试。不删除别人的草稿。

每日额度在学生这次操作第一次调用模型时减 1。同一次补叫和恢复复用不计。单次任务最多 2 次模型调用，输出不超过现有文本上限。

## 岗位

相邻图片、上下文一致的重复句才折叠，来源序号都留着。不同条件的相同句子不折叠。岗位名相同但地点、批次或期限不同时，确认按钮不可用，直到学生选择。

## 面试准备单

存在账号下。保存并继续把新岗位 ID 写上，提交给面试的方向改为岗位名。手填方向单独保留。

## 实现顺序

先做保存租约、版本、缓存状态和删除标记。再做确认页的三种状态。最后做读取、润色、岗位和样本验收。
