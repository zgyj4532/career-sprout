# 执行顺序

先保证保存、版本、缓存和删除能从中断里恢复，再做学生看到的确认页。

## 1. 保存和版本

- 确认单冻结内容。执行单带租约、目标 ID 和「记录已存在」。
- 补上简历 `revision` 与 `contentRevision`。定向草稿改看内容版本。
- 正文保存不写标题。改名和正文都用 `revision` 做条件更新。
- 缓存失效失败仍返回已保存，并只补做失效。面试和简历读取绕过 120 秒缓存。

## 2. 删除和导入恢复

- 删除中拒绝新建关联。清理可按原编号重试。
- 导入恢复看到删除中或已删除时停止，不重建简历。

## 3. 上传、解析和容量

- 流式落盘，原子预留容量。解析过程中执行大小、页数、像素和帧数限制。
- 解析放在可终止的隔离进程里。超时后确认进程退出，再释放与 PDF 共用的开关。
- 慢速上传不占开关。忙碌时保留文件并提供继续处理。

## 4. 确认页

- 默认展示整理结果和一句摘要。来源按问题展开。
- 区分原文没写、疑似漏读、读取失败。
- 日期全文、超长经历和其他原文材料写入可继续编辑的字段。
- 保存按钮写明档案和哪一份简历。只补简历空位。
- 保存后保留原件和变更记录。恢复不覆盖后续人工修改。

## 5. 润色、岗位、面试

- 润色采纳后显示尚未保存。
- 岗位只折叠相邻且上下文相同的重复句。冲突要学生选。
- 准备单支持取消、后退、刷新和跳转失败。

## 6. 验收

- 10 组内容、30 个文件。分图像提取、字段整理、润色和完整流程记录。
- 包含双栏、混合页、同名经历、无技能栏、超长段落和材料里的指令。
- 3 到 5 名没读过说明的学生试用，记录操作次数、是否重传、离开后能否继续、保存后能否接着面试。
- 假模型只测分支。真实模型记录和浏览器记录分开，不入库完整简历和密钥。

## 验证命令

- `npm run test:campus --prefix backend`
- `npm test --prefix frontend -- src/campus --maxWorkers=1 --no-file-parallelism`

## 回滚

新字段和草稿可以停止使用。不把定向草稿改回只看 `lastModified`。已写入档案的内容由学生自己改，脚本不批量覆盖。

## 2026-10-20 续做结果

本地可执行部分已实现并实际验证，见 `research/verification.md`。前端校园61项、后端校园79项与最新改动/Schema153项通过；最终修复另有提取19项、持久化/安全恢复、前端20项定向验证。实际浏览器验证原件恢复→保存→刷新→普通编辑、岗位截图→私有保存→原面试准备单、改名/删除与冲突保护；中文PDF实际渲染检查通过。

30个文件按10组记录，均能解析。最终复用同一批真实模型响应得到30份可核对结果，不能解读为30份内容完全正确；字段无法溯源时清空/排除并标问题，原文仍在。最终另对PDF/DOCX/PNG各发起一次真实Luna调用验证。保留失败批次与修复证据，不重传模型结果来刷通过率。

未完成的外部验收：3–5名新手学生、正式认证多账号、物理手机。2026-10-21用户决定改用新服务器，备案阻塞部署，因此新手试用与物理手机验收标记为BLOCKED_EXTERNAL；备案完成且验收环境可访问后恢复，不冒充通过，也不阻塞本地功能和布局开发。正式认证以部署文档的Evren/Resend方向为准；真人录音/扬声器已有用户确认。不自动归档、提交或推送。原本未批准的Issue后三项仍单独待讨论。
