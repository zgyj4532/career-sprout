# Interaction design

Extend the existing `/profile` view query with `experiences` and `skills`; preserve `materials` and the default. Retain a single editor owner for field values, form saves, import state and requests. Extend the narrow same-profile navigation exception only for valid view changes; keep other query, unload and true leave protections. Put labelled destinations below the heading, wrapping on phones, with active state and heading focus. Put the save action next to the active editor; communicate that it saves all current profile edits. Reveal and focus invalid fields in their own view rather than blocking save on a hidden input.

Reuse the existing upload, confirmation and canonical `/me` refresh. The primary path is upload, summary, confirm; detailed editing remains an opt-in disclosure, and conflicts use existing reviewed decisions rather than defaulting to replacement. Show destination links after acknowledged success. Keep the regular resume import entry behavior unchanged unless it explicitly opts in to the profile presentation. A successful write with a failed refresh needs a distinct refresh/retry state, not a second import. Maintain mobile page scroll and existing desktop shell. Revert by slice; no planned migration.
