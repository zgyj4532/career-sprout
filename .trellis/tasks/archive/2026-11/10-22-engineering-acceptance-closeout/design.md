# Engineering acceptance closeout design

## 1. Verification command
Keep npm run verify:phase1 as entry. Use process.execPath for Node children and a verified npm CLI under the selected Node installation (or prepend its bin and record resolved runtime). Refuse non-WSL explicitly instead of reporting success after a reduced subset. Fix APP_PROFILE/VITE_APP_PROFILE to campus-local for relevant steps;384MiB frontend build; one worker frontend tests. Default stages: read-only doctor, focused local-script behavior tests, backend test:campus, relevant shared schema/interview suites, explicitly declared campus lint scope, frontend campus tests, campus production build, isolated non-AI smoke/persistence. No hidden all-upstream assertions.

Offer explicit --include-upstream for additional whole-repo checks; store them as a separate scope, preserve their nonzero outcome. No force-exit/suppression/longer timeouts to disguise defects. Each step records command without secrets, cwd, actual Node, start/end, exit code, PASS/FAIL/BLOCKED_EXTERNAL/NOT_RUN. Persist report incrementally, distinguish process spawn error/signal/cancellation and cleanup failure; no double settlement of spawn error/exit. Failed required checks produce nonzero; externally unavailable acceptance is listed prominently and never called full acceptance. Only skip dependent steps; independent checks may finish.

## 2. Doctor
Bound external command timeouts. Validate WSL, selected Node/npm, Python, Docker daemon and docker compose version. Inspect manifests and lockfile root dependency/version declarations read-only; report structural inconsistency, not a claim npm ci was proven without installation. Check installed dependency presence separately. Probe5173/5002/27018/6380 and identify matching campus health/Compose ownership when safe. Free ports are not failure for an idle dev environment; known project service is reusable, foreign or unidentified occupied port is a conflict for startup. Never terminate it. Tool/privilege limitations are explicit UNKNOWN with next action. ASR/provider checks use existing config names found in code, presence/placeholders only; do not call paid providers for doctor. Preserve dotenv precedence and avoid logging URI credentials or command environments.

## 3. Isolated smoke and persistence
Refactor smoke-phase1/check-persist existing files rather than bolt on a second platform. Orchestrator allocates unique synthetic UID/database/import directory/run marker and owned loopback backend port; uses existing Mongo/Redis infrastructure without deleting volumes. Do not attach to a service just because a port responds; validate exact run identity. No global Clerk credential edits: isolated test subprocess uses deliberately local identity without affecting the developer server; report NOT formal-auth evidence.

Non-AI default smoke proves health, disabled route boundary, local bypass rejection, resume create/edit/read, API restart and reread of exact run marker, then cleanup only owned records/database/files/processes. PDF export if dependencies exist is tested separately from visual readability; browser phase checks actual Chinese document if changed. Missing infra produces explicit blocked smoke and required-gate nonzero, not invented success. Stop/restart only the child launched by verifier, never user's application/containers. Signal handlers cleanup in finally. Replace fixed ID with run-scoped evidence argument; do not reuse old evidence silently.

External AI/ASR/Clerk calls are not part of default deterministic acceptance. Preserve prior successful evidence; record current capability availability and remaining real-account gates. No new signup/mail/provider spending for an environment check.
