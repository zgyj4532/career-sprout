# 人工验收清单

本文件只列还要人做的事。没有逐项反馈之前，不要把这些标成 `PASS_HUMAN`。

## 已由自动测试覆盖，仍建议打开页面看一次

1. 打开 `http://127.0.0.1:5173`。
2. 保存一份简历，刷新后再打开，确认正文还在。
3. 导出 PDF，打开文件看中文。
4. 直接访问已关闭模块，应看到未开放，而不是空白成功。

失败时看页面文案里的 `status`、`code`、`at`、`requestId`，再在 API 日志搜 `[api-error]` 同一 `requestId`。

## 配一个文本模型后再测

在 `backend/.env` 只配一个：`GEMINI_API_KEY`、`OPENAI_API_KEY` 或 `GROQ_API_KEY`。不要把密钥贴到聊天或前端变量。

然后走：

1. 档案或项目经历里故意留空一段。
2. 粘贴岗位文本。
3. 生成定向简历。
4. 检查模型有没有编造经历、奖项或数字。缺信息应提示补充。
5. 人工改一处，保存，导出。

记录三层，不要混在一起：接口是否 200、生成内容是否守住已有事实、你是否接受这份结果。

当前没有密钥。`skill-gap` 和 `interview/start` 返回 403，标 `BLOCKED_EXTERNAL`。

## 配语音后再测

文本题、转写和播报是三件事。转写走当前 AI 供应商的音频接口；没有对应密钥时会失败。浏览器播报还要本机有中文音色。

真人流程：

1. 用已保存简历和岗位开始面试。
2. 听第一题。没有中文声音就不能算播报通过。
3. 用麦克风答，停止后应看到转写，而不是空文本被当成成功。
4. 再答一轮，确认下一题用到上一轮内容。
5. 刷新历史，问题和回答还在，且对应同一次面试。

拒绝麦克风、空录音、超时，都不应把失败写进成功记录。模拟音频和自动化浏览器不算这项通过。

## 配 Clerk 后再测

需要 `CLERK_SECRET_KEY` 和前端公钥。然后用两个测试账号：

1. 注册、登录、退出。
2. A 的简历、导出和面试历史，B 不能打开。
3. 错误密码不能进入，也不能落到本地开发身份。

没有正式账号时，内存库里的隔离测试不能代替这一项。
